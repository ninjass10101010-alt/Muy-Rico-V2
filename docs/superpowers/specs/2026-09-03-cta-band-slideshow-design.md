# CTA Band Photo Slideshow — Design

**Date:** 2026-09-03
**Scope:** `index.html` CTA band photo column only. No other pages, no backend changes.
**Status:** Approved (brainstorming session, same day)

## Goal

Turn the static concha photo in the homepage CTA band (redesigned earlier today) into an
auto-playing crossfade slideshow, fed by the same dashboard-managed gallery that powers
`gallery.html`. Baked-in local photos remain the always-working fallback.

## Decisions (from brainstorming)

| Question | Decision |
|---|---|
| Photo source | Hybrid: baked-in defaults, hydrated from `GET /api/gallery` when available |
| Controls | Autoplay + clickable dots (no arrows) |
| Mechanism | Approach A: CSS opacity crossfade + vanilla JS timer (no GSAP coupling, no libraries) |
| Slide count | All active gallery photos, capped at 8; fallback set = 5 baked-in photos |

## Non-Goals

- No swipe/drag gestures (dots + autoplay are the only controls).
- No changes to `motion.js`, the Workers API, or the dashboard.
- No new dependencies.
- No lightbox/zoom.

## Architecture

### Markup (index.html, CTA band section)

Current structure stays; the `.frame` becomes a slide stack:

```html
<figure class="cta-band-photo" data-motion="scale">
  <div class="frame cta-band-slides" aria-roledescription="carousel" aria-label="Muy Rico photos">
    <!-- N stacked <img class="cta-slide"> elements; first is active -->
  </div>
  <div class="cta-band-dots" role="tablist" aria-label="Choose photo">
    <!-- one <button class="cta-dot"> per slide, generated by JS -->
  </div>
  <figcaption class="cta-band-photo-caption lang-fade">…</figcaption>
</figure>
```

- Baked-in fallback slides (5, in order): `menu-conchas.webp` (Conchas), `menu-bolillos.webp`
  (Bolillos), `menu-cupcakes.webp` (Cupcakes), `menu-empanadas.webp` (Empanadas),
  `menu-cake.webp` (Pastel Personalizado / Custom Cake).
- Slides are server-rendered in the HTML (first paint shows slide 1 with no JS) — JS only
  renders dots and hydrates.
- The existing `data-motion="scale"` entrance on the figure is unchanged.
- All slide images `loading="lazy"` except slide 1 (in-viewport near CTA band bottom;
  keep eager for predictability). Explicit `width`/`height` attributes set per baked-in
  image dimensions to preserve CLS safety inside the fixed-ratio frame.

### CSS (style.css, CTA band block)

- `.cta-band-slides { position: relative; aspect-ratio: 3 / 2; }` — the frame's padding
  stays; inner wrapper or the frame itself fixes ratio so stacked absolutes never collapse.
- `.cta-slide { position: absolute; inset: <frame padding>; object-fit: cover; opacity: 0;
  transition: opacity 0.8s ease; }`, `.cta-slide.is-active { opacity: 1; }`.
- `.cta-band-dots { display: flex; gap: 0.5rem; justify-content: center; padding: 0.65rem 0 0; }`
  — dots are 8px cream circles at 35% opacity; active dot 100% opacity, slightly scaled.
  Focus-visible ring uses existing global clay outline.
- Caption stays beneath dots; fades via the existing `lang-fade` transition when text swaps.
- Reduced motion: under the site's existing global `prefers-reduced-motion` block the
  transition duration collapses automatically; JS additionally disables the autoplay timer
  (manual dot navigation only).
- `.no-gsap` independence: slideshow never touches GSAP; nothing to stub.

### JS (index.html inline script, near the existing hydration code)

New self-contained function `initCtaSlideshow()`:

- **State:** `slides[]` (img elements), `index`, `timer`, `PAUSE_MS = 5000`.
- **Dots:** generated once from initial slide count; `aria-current="true"` on active;
  click = jump to slide + reset timer.
- **Autoplay:** `setInterval`-style timer advanced only when: page visible
  (`visibilitychange`), not hovered (`mouseenter`/`mouseleave` on figure), no
  focus-within on figure, and `prefers-reduced-motion` is not set. Timer resets on any
  manual dot interaction.
- **Crossfade:** toggle `.is-active` on the next img; pure CSS handles the fade. Caption
  text swaps in the same tick (fade handled by `lang-fade` CSS transition on the caption).
- **Hydration:** after `initCtaSlideshow()` renders defaults, `fetch(ORDER_API +
  '/api/gallery')` (same `ORDER_API` constant the page already defines). On success with
  ≥1 photo: rebuild slides from response (`image_url`, `title`/`title_es` for alt +
  caption), cap 8, keep current index clamped, re-render dots. On error/empty: silently
  keep defaults (console-free, matching the page's quiet-failure hydration pattern).
- **Bilingual:** captions and alts stored per-slide as `es`/`en` strings; existing
  `setLang()` swaps caption text via the caption element's `data-es`/`data-en` attributes
  (re-applied after hydration re-render).
- **Cleanup:** single timer; no listeners on window beyond `visibilitychange` (one).

### API contract (read-only use)

`GET /api/gallery` → `{ photos: [{ id, image_url, title, title_es, product_id, … }] }`,
already active-filtered server-side. No auth. Unchanged in this work.

## Error Handling

- API unreachable / non-200 / empty `photos` → defaults remain. No user-visible error.
- Gallery photo fails to load (`onerror`) → swap that slide's src to the concha fallback
  and use its bilingual title; if the failing photo is active, advance once.
- Hydration arrives mid-session while user is on dot N → index clamped to new count.

## Accessibility

- `aria-roledescription="carousel"` + label on the frame.
- Dots: `<button>` in a `role="tablist"`, `aria-label` "Slide N: <title>",
  `aria-current` on active. Keyboard reachable (global focus ring applies).
- Alt text per slide from gallery `title`/`title_es` (or baked-in names). Alt language
  follows active site language at hydration time; stored bilingual thereafter.
- Autoplay pauses on hover and focus-within so screen-reader/keyboard users are never
  fighting a moving target.

## Performance

- Fallback images already ship (`menu-*.webp`, 49–154KB each); slide 1 eager, rest lazy.
- Hydrated R2 URLs render as stacked imgs with `loading="lazy"` — they load when the
  band scrolls into view, not on page load; max 8 images total.
- Zero CLS: frame aspect-ratio fixed before and after hydration.
- No layout animations; opacity only.

## Testing (extend existing Playwright CTA-band suite)

1. Stack renders: N imgs, first `.is-active`, others `opacity: 0`.
2. Dots render (count matches slides), active state tracks current slide.
3. Autoplay: advance observed within ~6s (fake timers not available; use real wait).
4. Dot click: jumps to target slide, timer resets.
5. Hover on figure pauses advance (no change after >5.5s while hovered).
6. Reduced-motion: no autoplay; manual dots still work.
7. API failure (route abort): baked-in defaults remain, no errors.
8. Hydration (route mock with 2 test photos): slides rebuilt from API, dots re-render,
   captions bilingual on `setLang`.
9. No horizontal overflow at 1440/900/861/390/320 (existing checks kept).
10. Zero CLS: frame box identical before/after hydration and during fades.

## Risks

- Gallery photos have arbitrary aspect ratios → object-fit: cover crops; acceptable
  (gallery is product photography, center-ish subjects).
- `/api/gallery` could return many photos → client caps at 8; no server change.
- Autoplay + `data-motion` entrance could double-animate on first view → entrance is
  figure-level scale, slideshow is opacity between imgs; orthogonal, no conflict.
